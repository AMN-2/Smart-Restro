# URYPOS QA — 2026-10-04

## Confirmed root cause
Chromium reproduced an empty main area after navigating Table → Menu, even with products in the store. Vue reported: "Component inside <Transition> renders non-element root node that cannot be animated." The route transition now animates a keyed DOM wrapper, preserving multi-root page components.

## Fixes
- Keyed route wrapper and unique Table route (root redirects to /Table).
- Table menu and invoice are loaded before replacing the active ticket; failed loads preserve the existing cart. Denied access does not navigate.
- Table switching clears stale invoice references, search filters, pagination, customer and takeaway context; concurrent opens are blocked.
- Removed the redundant unscoped menu request after loading a room menu. Room table refresh ignores outdated responses.
- Preserve unsent order and item notes when considering live refresh.
- Prevent duplicate order submission, handle cancellation without unhandled promise rejection, report network failure while preserving cart.
- Fit product columns beside desktop cart; preserve reduced-motion settings including animation delays.
- Modal Tab/Shift+Tab focus containment and focus restoration.
- Correct absolute/relative product image URLs and Desk URL port.
- Remove nonexistent opening-balance input handler.
- Closing amounts stored independently per payment row; reset aggregates before refresh, aggregate taxes across invoices, count invoices, calculate reconciliation from opening + receipts and entered closing amount.

## Limits
Browser API requests were intercepted, and business mutations were mocked. No production orders, payments, shift closings or printer jobs were created. Authenticated production data, server permission enforcement, real payment settlement, printers, and multi-device websocket end-to-end behavior were not tested. This is a regression/functional QA pass, not a guarantee that all possible defects are absent.
